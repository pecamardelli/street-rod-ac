STREET ROD – POST-RACE OUTPUT HANDLING GUIDELINES
PURPOSE

Define a safe, deterministic, and user-respectful process for handling race result files generated by the StreetRodRaceApp Python script after Assetto Corsa exits.

The system must be robust against garbage files, partial writes, crashes, and foreign data, while never interfering with the base game or other tools.

CORE PRINCIPLES

The Assetto Corsa output directory is a shared environment.

A dedicated subfolder reduces noise but does not guarantee cleanliness.

Street Rod Manager owns only files it can positively identify.

All operations must be reversible, non-destructive, and atomic.

Validation is mandatory at every stage.

Ignoring unknown data is always safer than guessing.

OUTPUT FOLDER CONVENTION

The StreetRodRaceApp writes result files to:

Documents\Assetto Corsa\out\StreetRodRaceApp

This folder is considered a logical inbox, not application storage.

Street Rod Manager must not assume:

The folder exists

The folder is empty

The folder contains only valid JSON

The folder contains only Street Rod data

POST-RACE EXECUTION ORDER

ASSETTO CORSA EXIT CONFIRMATION

Ensure the Assetto Corsa process has fully terminated

Do not scan while AC is running

Avoid reading partially written files

FOLDER ENUMERATION (READ-ONLY)

Enumerate all files in out\StreetRod

Do not sort by time

Do not assume ordering

Do not mutate files at this stage

FIRST-PASS FILTERING
Immediately ignore any file that:

Does not have a .json extension

Does not match a UUID-based filename

Has zero size

Is locked or unreadable

CONTENT VALIDATION
A file is considered a Street Rod candidate only if:

It is valid JSON

It contains a metadata.schema_version field

It contains a metadata.source field equal to "StreetRodRaceApp"

It contains a session.session_id field

It contains a session.start_timestamp field

Files without a valid signature are not owned by Street Rod Manager.

DEDUPLICATION

Use session_id as the primary identity

Filename uniqueness is not sufficient

If a session_id already exists in storage, ignore the file

OWNERSHIP TRANSFER (ATOMIC MOVE)

Move validated files into application-owned storage

Never parse files in place

Never copy and leave originals behind

Once moved, files are immutable artifacts

SECOND-PASS VALIDATION

Re-validate JSON after move

Confirm integrity and completeness

Reject corrupted or truncated files

PROCESSING

Parse JSON

Persist structured data (e.g., LiteDB)

Apply game logic and progression rules

Log successful import

GARBAGE HANDLING STRATEGY

If non-Street Rod files exist in the folder:

Ignore them completely

Do not delete

Do not rename

Do not treat as errors

Optionally log at debug level only

Street Rod Manager must remain stable regardless of foreign data.

QUARANTINE STRATEGY (OPTIONAL)

If a file:

Matches the naming convention

But fails schema validation

It may be moved to:

Documents\Assetto Corsa\out\StreetRodRaceApp_quarantine

Rules:

Never auto-delete

Clearly log the reason

Allow manual inspection

STRICTLY FORBIDDEN ACTIONS

Cleaning the folder automatically

Assuming only one result file exists

Processing “latest file only”

Trusting timestamps over session IDs

Overwriting or restoring entire folders

Crashing due to unexpected files

FAILURE RESILIENCE

This system must survive:

AC crashes

App crashes

Duplicate files

Partial writes

User interference

Other Python apps misbehaving

Files must remain safe and recoverable in all cases.

FINAL STREET ROD RULE

Even inside our own folder, we trust nothing we didn’t sign.

If multiple tools dump files there, Street Rod Manager must not even notice.

END OF GUIDELINES
