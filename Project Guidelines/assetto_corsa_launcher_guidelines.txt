STREET ROD MANAGER
ASSETTO CORSA LAUNCHER AND EXECUTION SYSTEM GUIDELINES

PURPOSE
This document defines the official guidelines for launching Assetto Corsa races and the Assetto Corsa showroom from Street Rod Manager.
The objective is to ensure that all configuration changes are safely applied before execution and that Assetto Corsa is launched in a fully prepared, deterministic state.

Street Rod Manager does not “launch a game”.
It executes a prepared simulation state.

CORE PHILOSOPHY

Launching Assetto Corsa is the final step of a controlled pipeline.
All configuration, validation, and preparation must be completed before the executable is started.

Street Rod Manager is responsible for intent declaration, configuration preparation, and execution control.
Assetto Corsa is responsible for runtime behavior once launched.

CENTRALIZED EXECUTION RULE (NON-NEGOTIABLE)

There must be exactly one system responsible for:

Preparing configuration for execution
Launching Assetto Corsa
Launching the Assetto Corsa showroom
Tracking the execution lifecycle

No other system may:

Call the Assetto Corsa executable
Pass launch arguments
Modify configuration during execution

This rule prevents race conditions, partial configuration application, and inconsistent runtime behavior.

EXECUTION PIPELINE (MANDATORY ORDER)

DECLARE INTENT

Higher-level systems declare what should be executed.

Examples:

Start a race session
Open the showroom
Preview a car

At this stage:

No files are modified
No validation is skipped

PREPARE CONFIGURATION

The launcher requests all required configuration intents, including:

Global configuration intents
Car-specific intents
Track and session intents
The configuration system:
Applies minimal and reversible changes
Validates the resulting state
Logs ownership and intent mapping
If configuration preparation fails, the launch must be aborted.

LOCK EXECUTION STATE

Once configuration is prepared:
Configuration becomes read-only
No UI or background system may mutate INI files
The system enters execution lock
This prevents corruption caused by late changes.

EXECUTE

Only after successful preparation and locking:

Assetto Corsa is launched
Showroom or race mode is selected
Control is handed over to the game
Street Rod Manager does not interfere during execution.

MONITOR (PASSIVE)

While Assetto Corsa is running:

Observe process lifecycle
Do not modify configuration
Do not reapply intents
The simulation fully owns runtime state.

POST-EXECUTION CLEANUP

After Assetto Corsa exits:

Release execution lock
Optionally restore user-owned configuration
Persist gameplay results
Write execution logs
Cleanup is explicit and intentional.

LAUNCH MODES (EXPLICIT SEPARATION)

RACE MODE

Full configuration preparation
Strict validation
Highest safety requirements

SHOWROOM MODE

Minimal configuration changes
No gameplay systems involved
Visual-only intent

FAILURE HANDLING

If any of the following fail:

Configuration write
Validation
Lock acquisition

Then:

Abort launch
Restore previous configuration state
Log detailed diagnostics
Notify the user clearly
Assetto Corsa must never be launched in a partially prepared state.

STATE OWNERSHIP RULES

During preparation: Street Rod Manager owns configuration
During execution: Assetto Corsa owns runtime state
After exit: ownership returns to Street Rod Manager
Ownership must never overlap.

USER TRUST PRINCIPLE

Users must feel confident that:
Their configuration will not be corrupted
The game remains usable outside Street Rod Manager
No silent or hidden changes occur
All actions must be explicit and intentional.

STRICT ANTI-PATTERNS

Launching Assetto Corsa directly from UI logic
Modifying INI files after execution starts
Automatic relaunch without state reset
Mid-session configuration changes
Global flags without proper locking
Assuming Assetto Corsa finished writing files

MENTAL MODEL SUMMARY

Launching is a transaction
Configuration changes are preparation
Execution is read-only
Cleanup is explicit
Control is centralized
