STREET ROD MANAGER
ASSETTO CORSA PYTHON RACE APP – OFFICIAL GUIDELINES

PURPOSE

This document defines the official guidelines for the Assetto Corsa Python race application used by Street Rod Manager.

The Python app is a lightweight telemetry observer and enforcement layer.
Its role is to observe race data, enforce Street Rod–style crash consequences, and emit a single authoritative session result.

The script must remain simple, deterministic, and performance-safe.

CORE PHILOSOPHY

The Python app does not simulate gameplay systems.
It does not control race flow.
It does not modify physics or configuration.

It observes, aggregates, enforces loss of control when required, and reports facts.

Street Rod–style behavior means:

A hard crash ends the race

The player cannot continue

The outcome is final and deterministic

RESPONSIBILITIES

The Python app is responsible for:

Sampling race telemetry at a low, fixed frequency

Tracking basic race metrics

Receiving crash intensity values from an external crash-detection script

Determining when a crash exceeds the hard crash threshold

Enforcing crash mode via player control lock

Aggregating final session data

Writing exactly one output file at session end

NON-RESPONSIBILITIES (STRICT)

The Python app must NOT:

Modify INI files

Change physics parameters

Stall or kill the engine internally

End or restart the race session

Apply rewards or penalties

Persist data outside the AC out folder

Communicate with databases

Perform networking

Render heavy UI

All higher-level decisions belong to Street Rod Manager.

PERFORMANCE CONSTRAINTS

Telemetry sampling must be fixed-rate (not per-frame)

Minimal state only

No heavy math

No large allocations

No background threads

No continuous file I/O

The script must be effectively invisible to performance.

CRASH INTENSITY HANDLING

Crash detection is performed internally using AC's telemetry API.

This script:

Reads G-force values from ac.getCarState() using acsys.CS.AccG

Calculates 3D G-force magnitude: sqrt(g_x² + g_y² + g_z²)

Tracks frame-to-frame G-force delta to detect sudden impacts

Compares G-force change against a predefined hard crash threshold

Implementation details:

G-forces are read as [lateral, vertical, longitudinal] array

Total G-force magnitude is calculated using 3D vector math

Crash intensity = abs(current_total_g - previous_total_g)

A cooldown period prevents multiple detections from the same crash

Suggested thresholds (subject to tuning):

Hard crash threshold: 100G change (game over event)

Cooldown period: 5-10 seconds

Rules:

No collision geometry analysis

No surface or contact logic

No damage modeling

A crash is either:

Below threshold (ignored)

Above threshold (hard crash)

CRASH MODE ACTIVATION

When crash intensity exceeds the hard crash threshold:

Crash mode is activated immediately

The state is irreversible for the session

Crash mode must activate only once

CRASH MODE ENFORCEMENT (MANDATORY)

When crash mode is active:

Throttle input is forced to zero

Brake input is forced to maximum

Player input is continuously overridden

Control is never restored

This is a control lock, not a physics modification.

The goal is to prevent continuation, not simulate mechanical failure.

USER FEEDBACK

Upon crash mode activation:

Display a clear, unambiguous message

Example intent:
“You crashed hard. The race is over.”

No retries, countdowns, or ambiguity.

SESSION IDENTIFICATION (CRITICAL)

Each race session must generate a UUID:

Generated once per session

Immutable

Used as the authoritative session identifier

The UUID must be used as:

session_id inside the output data

The basis for the output filename

Human-readable identifiers must NOT be used as filenames.

OUTPUT FILE RULES

Exactly one output file per session

Written only once, at session end

Stored in:
Documents\Assetto Corsa\out\StreetRodAC

Filename format: {uuid}.json

The script must create the StreetRodAC folder if it doesn't exist

The out\StreetRodAC folder is treated as a temporary drop zone.

OUTPUT DATA CONTENT

The output file must be self-contained and authoritative.

Top-level structure includes:

metadata object containing:
  schema_version
  script_version
  generated_at timestamp

session object containing:
  session_id (UUID)
  start_timestamp
  end_timestamp
  duration_seconds
  track_id
  track_layout (if applicable)

participants array containing data for all racers:
  For each participant:
    driver_name
    car_name
    performance object:
      final_position
      laps_completed
      best_lap_time_ms
      total_race_time_ms
      max_speed_kmh
      distance_km
      fuel_consumed_liters
    crash object:
      crashed (true/false)
      crash_intensities_g (array)
      max_crash_intensity_g
      crash_timestamp (optional)

The output reports facts only.
It does not determine career outcomes.

OUTPUT FORMAT

Machine-readable (e.g. JSON)

Deterministic

No post-write modification

Immutable once written

FAILURE TOLERANCE

If the script fails:

Assetto Corsa must continue running

The race must not crash

Partial or missing output is acceptable

Street Rod Manager must treat missing or invalid output as a failed session.

Implementation note:

For initial development, assume the happy path

All telemetry data is available and valid

Output writes succeed

Edge case handling can be added incrementally as issues are discovered

ANTI-PATTERNS (STRICTLY FORBIDDEN)

Encoding metadata in filenames

Parsing filenames for logic

Writing directly to application storage

Writing multiple output files per session

Continuous writes during the race

Physics manipulation

Engine control hacks

Session termination attempts

MENTAL MODEL SUMMARY

UUID identifies the session

Python app observes and enforces loss

Crash mode locks control

One immutable output file is written

Street Rod Manager ingests and decides consequences

STREET ROD MANAGER
ASSETTO CORSA RACE SESSION – JSON SCHEMA

SCHEMA OVERVIEW

Each race session produces exactly one immutable JSON file.
This file is the authoritative record of the session.

The schema is designed to:

Be self-contained

Support forward compatibility

Allow database rebuilds

Enable debugging and reprocessing

TOP-LEVEL STRUCTURE

The JSON document consists of the following top-level objects:

metadata

session

participants

No additional top-level objects are allowed.

METADATA OBJECT

Purpose:
Identifies schema, script, and compatibility information.

Fields:

schema_version
Type: string
Description: Version of this JSON schema
Example: "1.0"

script_version
Type: string
Description: Version of the Python race script
Example: "1.2.0"

generated_at
Type: string (ISO 8601 timestamp)
Description: Time at which the file was written

SESSION OBJECT

Purpose:
Uniquely identifies the race session, its timing, and track information.

Fields:

session_id
Type: string (UUID)
Description: Immutable unique identifier for the session

start_timestamp
Type: string (ISO 8601 timestamp)
Description: Session start time

end_timestamp
Type: string (ISO 8601 timestamp)
Description: Session end time

duration_seconds
Type: number
Description: Total session duration

track_id
Type: string
Description: Assetto Corsa track identifier

track_layout
Type: string or null
Description: Track configuration or layout

PARTICIPANTS ARRAY

Purpose:
Contains data for all participants in the race session.

Type: array of participant objects

Each participant object contains:

driver_name
Type: string
Description: Driver name

car_name
Type: string
Description: Assetto Corsa car identifier

performance
Type: object
Description: Performance metrics for this participant

crash
Type: object
Description: Crash data for this participant

PERFORMANCE OBJECT (nested within each participant)

Purpose:
Summarizes race performance metrics for the participant.

Fields:

final_position
Type: integer or null
Description: Final classified position

laps_completed
Type: integer
Description: Number of laps completed

best_lap_time_ms
Type: number or null
Description: Best lap time in milliseconds

total_race_time_ms
Type: number
Description: Total time spent racing in milliseconds

max_speed_kmh
Type: number
Description: Maximum speed achieved in km/h

distance_km
Type: number
Description: Total distance covered in kilometers

fuel_consumed_liters
Type: number
Description: Total fuel consumed in liters

CRASH OBJECT (nested within each participant)

Purpose:
Reports crash-related outcomes for the participant.

Fields:

crashed
Type: boolean
Description: Whether a hard crash occurred (above threshold)

crash_intensities_g
Type: array of numbers
Description: List of all crash G-force values recorded

max_crash_intensity_g
Type: number
Description: Maximum crash intensity observed in G-forces

crash_timestamp
Type: string (ISO 8601 timestamp) or null
Description: Time of hard crash occurrence (if crashed)

GENERAL RULES

All timestamps must use ISO 8601 format

Numeric values must use real-world units

Optional fields must be explicitly null if not applicable

No derived or business logic fields are allowed

The file must not be modified after creation

VERSIONING RULES

schema_version must change only when structure changes

New optional fields may be added without breaking compatibility

Existing fields must never change meaning

IMMUTABILITY GUARANTEE

Once written:

The JSON file is never modified

The file is never re-written

Corrections require a new session file
