PROJECT CONTEXT: ASSETTO CORSA STREET ROD META-GAME

OVERVIEW This project aims to create a Street Rod–style meta-game layer
on top of Assetto Corsa (AC), without modifying AC core files. Assetto
Corsa is treated purely as a physics and rendering engine. All game
logic, progression, economy, and persistence are implemented externally
in a standalone Windows executable.

The end result is a career-based experience inspired by classic Street
Rod gameplay: - Buying and selling cars - Upgrading engines, drivetrain,
suspension - Managing money, wear, and damage - Running races or
free-roam sessions for profit - Persistent consequences between sessions

TECH STACK - Language: C# - Runtime: .NET 10 LTS - OS: Windows - IDE:
Visual Studio Community - UI Framework: WPF (MVVM pattern) - Storage:
SQLite initially (possible MongoDB later) - Target Architecture: x64

HIGH-LEVEL ARCHITECTURE The solution is split into three conceptual
layers:

1)  META-GAME / GAME LOGIC LAYER (C#)
    -   Player progression
    -   Economy (money, costs, payouts)
    -   Car ownership and inventory
    -   Upgrade system
    -   Wear and damage persistence
    -   Save/load system
2)  ASSETTO CORSA INTEGRATION LAYER
    -   Launching AC sessions via Content Manager CLI
    -   Generating race/session configurations
    -   Cloning and modifying car data folders
    -   Writing physics INI files before each session
    -   Reading race results after session completion
    -   Optional Python in-game apps for HUD/telemetry
3)  DATA / PERSISTENCE LAYER
    -   Save-game files (JSON or SQLite)
    -   Car templates and upgrade definitions
    -   Versioned data with migration support

ASSETTO CORSA INTEGRATION DETAILS - No memory injection or runtime
physics hacking - No modification of AC core binaries - Physics changes
are applied by cloning car folders and editing INI files - Any physics
change requires restarting the AC session (acceptable by design)

Key files manipulated: - engine.ini - drivetrain.ini - suspensions.ini -
power.lut - damage-related parameters

CONTENT MANAGER is used as: - Session launcher - Race configuration
interface - CSP configuration injector

USER INTERFACE STRATEGY - Primary UI: External WPF application (garage,
shop, events, launcher) - Secondary UI: Minimal in-game Python app (HUD,
race results, damage display)

The WPF app acts as: - A launcher (similar to Content Manager) - A
garage/workshop - A career manager

GAMEPLAY PRINCIPLES - Persistent consequences: damage, wear, and mileage
matter - Money is always at risk - Repairs and upgrades cost time and
money - No instant resets without consequences - Designed to feel like a
simulation-flavored management game

AI ASSISTANCE CONTEXT (CLAUDE) Claude is used as a development assistant
for: - C# and WPF code generation - MVVM architecture support - INI file
analysis and generation - Physics parameter tuning suggestions - Code
refactoring and documentation

Claude should assume: - Strong software engineering background -
Familiarity with C#, .NET, WPF, MVVM - Understanding that Assetto Corsa
is not being modified internally - Emphasis on clean architecture,
maintainability, and tooling

NON-GOALS / CONSTRAINTS - No true open-world AI traffic simulation - No
hot-reloading of physics - No AC binary patching - No DRM or online
multiplayer focus (initially)

PROJECT PHILOSOPHY Treat this as a real software product: - Clean
architecture - Versioned saves - Logging and error handling - Extensible
design - Tooling-first mindset
