## Executive summary

35 bugs, 64 stability, 20 security/integrity, 6 drifting + 7 extract duplicates, 15 pattern deviations, 19 performance, 15 clean-code items. The AC-install integrity design (`CarDataOverlay`) is sound in its happy path. It has three holes that can leave a user's AC install modified:

1. **No global exception handlers** (`App.xaml.cs`). Any unhandled exception during a race kills the process before the launcher's `finally` restores car data, sounds, clones and race.ini. There are 21 `async void` sites and 14 of them have unguarded code. Fix: wire `DispatcherUnhandledException`, `AppDomain.UnhandledException` and `UnobservedTaskException` to log, save, restore (when `acs.exe` is not running) and flush.
2. **`race.ini` is overwritten and never restored.** This breaks the documented rule "INI Files: … always restore after AC exits" (`docs/CLAUDE.md:19`). `IniWriter` also drops comments, adds a BOM and grows files. Fix: back up and restore race.ini through the same manifest/`finally`/start-up path as car data, and use one INI writer.
3. **The race-result pipeline loses or doubles results.** The Lua app can write two results for one race and writes to the wrong Documents folder on OneDrive machines. Orphan results are always quarantined. Quitting AC mid-race voids a losing pink slip. An opponent-name mismatch crashes the processor (the CS8602 warning). Fix: latch the Lua session, use `ac.getFolder(ac.FolderID.ACDocuments)`, carry a race-context id through race.ini into the JSON, and process in one transaction.

Also worth knowing: `CarDataOverlay.Restore` deletes the kept originals when the manifest reads as null (0-byte file after a power loss). Several gameplay systems are silently broken: race events never pay out, newspaper events ignore their track, the challenge-acceptance test bypass shipped, and pink-slipped cars lose their parts.

## BUGS (must fix)

### AC install / race pipeline integrity

- ✔ **Street Rod AC/App.xaml.cs:101-206** — none of `DispatcherUnhandledException`, `AppDomain.CurrentDomain.UnhandledException`, `TaskScheduler.UnobservedTaskException` is wired.
  - **Why:** WPF docs say that when `DispatcherUnhandledException` is not handled, "the application shuts down immediately… no other Application events are raised", so any code that must run before shutdown belongs in that handler. The launcher's `finally` (`Services/Assetto Corsa/AssettoCorsaLauncher.cs:212-228`) and `OnExit` never run, so `content\cars` data, sfx swaps, the `__sr_opponent` clone and race.ini stay modified until the next start, the game state is not saved and the crash is not logged (CWE-459). 14 of 21 `async void` sites and `AsyncRelayCommand.Execute` (`ViewModels/AsyncRelayCommand.cs:31`, try/finally, no catch) let exceptions escape.
  - **Fix:** in the `App` ctor, wire all three: log Critical, save `CurrentGameState`, run `CarDataOverlay.RestoreAll()` plus an INI restore when `acs.exe` is not running, then `Log.CloseAndFlush()`. Set `e.Handled = true` where recoverable. Add a catch to `AsyncRelayCommand.Execute`.
- ✔ **Services/Configuration/IniModificationService.cs:151-166, 241-249** — drag race and free run `File.WriteAllText` the whole `Documents\Assetto Corsa\cfg\race.ini`: no backup, no restore (the service has no `Restore` at all).
  - **Why:** `docs/CLAUDE.md:19` and `docs/ac-integration/ini-modification.md:4,41,55-56` require every change to be restored after AC exits. After a race, race.ini keeps `MODE=sr_race`, `__CM_NEW_MODE_USED` and our cars, which affects the user's next normal AC/CM session.
  - **Fix:** keep the original bytes under `%AppData%\StreetRodAC\AcRestore` with a manifest, restore them in the launcher's `finally` and at start-up (same path as `CarDataOverlay`), and write through temp + `File.Move`.
- ✔ **Services/Assetto Corsa/CarDataOverlay.cs:247 → 270** — `DeserializeObject<Manifest>(...) ?? new Manifest { CarId = carId }` treats a manifest that reads as null (0-byte after a power loss or kill, or literally `null`) as "nothing changed". `Directory.Delete(keep, true)` then deletes the kept originals, so the car stays on race data for good.
  - **Fix:** treat a null or unparsable manifest as corrupt: throw, keep the folder, surface it to the player. Never delete `keep` unless every entry was put back.
- **Services/Assetto Corsa/CarDataOverlay.cs:161** — the manifest is written with `File.WriteAllText` (no temp file, no `Flush(true)`), and the car files are overwritten right after it (:166-174). This is the trigger for the bug above.
  - **Fix:** write `manifest.tmp` through a `FileStream`, call `Flush(flushToDisk: true)`, then `File.Move` it into place before touching `content\cars`.
- ✔ **Street Rod AC/App.xaml.cs:231-240** — the start-up `RestoreAll` runs without checking for a running `acs.exe`. Reopening the app during a race, or after an app crash with AC still up, deletes the clone and the unpacked data folder from under the running game, and the bank move fails while FMOD holds it, leaving a half-restored car.
  - **Fix:** if `Process.GetProcessesByName("acs")` is non-empty, defer the restore until it exits and tell the player.
- ✔ **apps/lua/sr_race_manager/sr_race_manager.lua:378-380** — after `endSession()` clears `sessionActive`, the next 0.1 s tick calls `initializeSession()` again: new UUID, reset `carData` (`crashed=false`). A ≥threshold g spike in the 5 s before quit (the car still tumbling, or hitting a wall past the finish) writes a **second result file** with a different `session_id`. Ingestion dedups by id, so the wager, rep and odometer apply twice, or a WIN comes with a CRASH.
  - **Fix:** add a `sessionEnded` latch, and return early from the interval once the race has ended.
- ✔ **apps/lua/sr_race_manager/sr_race_manager.lua:329** vs **Services/Race/RaceResultIngestionService.cs:287-288** — Lua writes under `%USERPROFILE%\Documents`, while C# reads `SpecialFolder.MyDocuments`. With OneDrive-redirected Documents (a common Windows 11 default), every result is lost.
  - **Fix:** `ac.getFolder(ac.FolderID.ACDocuments) .. "\\out\\sr_race_manager"` (confirmed in the SDK's `common/ac_enums.lua`), or pass the path through race.ini.
- **apps/lua/sr_race_manager/sr_race_manager.lua:305** — participants are built with `pairs(carData)`, so the order is undefined. `RaceResultProcessor` falls back to "first participant is the player" when names don't match, which is always the case for orphans (null context). The outcome is inverted.
  - **Fix:** iterate `for i = 0, sim.carsCount-1`, and add `car_index`/`is_player` to the schema.
- ✔ **Street Rod AC/App.xaml.cs:293-304** + **Services/Race/RaceResultProcessor.cs:53-57** — orphan results are processed at start-up before any save is loaded. The processor throws "No active game state", so every orphan (the race whose app crashed, which is what this path is for) is quarantined and never applied.

## TEST COVERAGE

There are no test projects. `tools/EngineBench` is the only regression harness: it covers engine curves and rated-build checks, but `rated` always exits 0, so it can't gate anything yet. Where tests would pay off most, given this report:

1. **`CarDataOverlay` apply/restore/clone cleanup** against a temp "AC install": the empty-manifest, read-only-file and missing-kept-file cases found above.
2. **race.ini backup/restore round trip** (once it exists) and `IniWriter` byte-identical round trip: the comment-loss and blank-line growth bugs.
3. **`RaceResultProcessor`** with fixture JSONs: name mismatch, nulls, bad timestamp, duplicate session, orphan with no context.
4. **Script VM** golden tests plus malformed bytecode (bad jumps, negative arg counts, string growth).
5. **One `AcSpecs` parser** and **one `CarValuation`**: table tests over real `ui_car.json` spec strings.

Suggested layout: `tests/StreetRodAC.Parts.Tests` as a plain `net10.0` project linking `Parts/**` the way EngineBench does, and `tests/StreetRodAC.Tests` as `net10.0-windows` for services.

## DEPENDENCIES

- Vulnerable 0, deprecated 0. Outdated: Newtonsoft.Json 13.0.3 → 13.0.4 (all three projects, which agree on the version), Serilog 4.3.0 → 4.4.0, JetBrains.Annotations 2023.3.0 → 2026.2.0. The annotations are compile-time only and redundant with `Nullable=enable`; consider removing them.
- Local `actools` DLLs are referenced from a **Debug** build in a sibling checkout (`..\actools\Output\x64\Debug`), unversioned: a reproducibility risk. Record the expected actools commit in `docs/`.
- SlimDX (unmaintained since ~2012) is needed only by AcTools.Render; Vortice.Direct3D9 3.8.3 already covers the D3D9 side.
- FMOD is loaded from the AC install at runtime. The struct layouts are verified against FMOD 1.08 headers; the version assumption isn't documented in the repo.
- `nuget.config` clears sources and lists only nuget.org. .NET 10 is LTS.

## POSITIVE PATTERNS

- `CarDataOverlay` orders its work as copy originals → write manifest → change; restores in the launcher's `finally` and at start-up, isolating each car; writes the clone marker first and deletes it last; and every `content\cars` scanner goes through `AcCarFolder.InstalledCars`, which skips clones.
- Script VM: step budget (500k), depth limit (24), sparse arrays, and no file or process access from scripts. `ScriptClass.Load` validates section sizes with long arithmetic. Graph walks are capped (8 alias hops, 16 equivalent slots, 32-deep class chains with cycle check).
- FMOD DSP plugins use `delegate* unmanaged` + `[UnmanagedCallersOnly]`, so no delegate rooting is needed. Struct offsets match FMOD 1.08. DLLs load by full path through a resolver.
- The D3D9Ex bridge follows the Microsoft D3DImage guidance (`Direct3DCreate9Ex`, Multithreaded|FpuPreserve, `SetBackBuffer(null)` before release, rebind on front-buffer restore).
- Race-result JSON is strictly validated and quarantined with an error sidecar; the filename must be a UUID. No `TypeNameHandling`, `BinaryFormatter` or custom `BsonMapper` anywhere.
- `UsedPartsScreenViewModel` is the model screen: a guarded async `Enter`, a virtualized recycling list, a reload on a new day. Stale async results are guarded with version tokens across Garage, DealerLot and PartsWorkbench.
- Converter: `--replace` and stale-pack removal only touch folders with a `pack.json`; unmatched rules exit 1; output JSON uses `SortedDictionary`; per-part conversion errors are caught.
- `GameTimeScheduler` isolates failing tasks.

## Coverage gaps in this audit

- **FMOD 2.02 DSP plugin docs:** the fetch returned empty. The native review used the FMOD 1.08 header layouts and general FMOD knowledge; whether `Bank_Unload` completes asynchronously and whether 1.08 exports `FlushCommands` are unverified.
- **CSP native APIs** used by the Lua app (`ac.tryToStart`, `ac.shutdownAssettoCorsa`, `ac.onCarJumped`, `physics.*`) aren't declared in the public acc-lua-sdk, so they couldn't be checked.
- **AcTools / AcTools.Render / SlimDX internals** (KN5 parsing of untrusted car models) are out of repo scope; only how the game calls them was reviewed.
- **AC-side components in the install** (`sr_race` new mode, FFB limiter under `C:\GAMES\...\extension`) are out of scope.
- **Controller re-reads:** the controller personally re-read the lines of the ✔ items (every top-severity BUG and most SECURITY items). The remaining entries rely on the slice reviewer's verification against the cited lines.
- No runtime checks: the game, AC, the converter and EngineBench were not run, by design.
